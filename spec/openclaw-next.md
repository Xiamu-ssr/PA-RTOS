# 豆豆 4：实现边界

安装包、线上迁移与发布状态以 Release 记录为准；实际验收范围见各版本验证记录。当前交互以用户确认的五栏与伙伴页为准。

## 交互

- 底部五个图标：聊天、动态、交办、书架、资源库。没有抽屉和旁聊。
- 聊天头像与设置同进伙伴页。圆框直径为 82.5，名字紧贴圆框下方、使用轻柔的常规字重；头像悬浮覆盖，短聊天靠近输入框，历史可滚到顶部浮层背后。
- 自己和豆豆的消息均可选取局部文字、复制或引用。多条选段进入输入框上方，可逐条移除，发送时与正文、附件和动态/书籍引用一起交付；只有引用也可发送。服务端核对原消息与选段，角色由原消息决定；历史保存当时选段，不因后续删除或改动原消息而改写已发引用。
- 伙伴页同一行展示豆豆与我的账户，名称放圆形头像下方，账户圆为豆豆的 70%，靠右相依且不旋转，点击 PA 选择三种外观；下方是实际设备槽、画面及模型/Soul/记忆/连接器。设备命名为本机或品牌，重名加 a/b/c。单击画面放大，双击设备进入详情。仅在可见时每秒最多读取一帧；无桌面的 Cloud 不伪造画面。
- 模型两列三行：五类能力与刷新目录。连接成功时按钮圆形扩散，只播放一次。
- 动态展示原文节选和图片；浏览、点赞、评论数仅在实际取得后出现；不显示踩。聊一聊先引用到主会话。
- 交办统一名称、刚完成、下一步，可选右侧小圆环；摘要各不超过 40 字，优先保留关键事实和数字，详情保留全文。
- 书卡直接读原文，另有笔记/共读按钮；加书先聊天。详情不重复显示标题、修订栏与交谈按钮；原文页仅保留阅读。EPUB 分章节分页，提供字号、纸色与续读，用户进度不覆盖豆豆进度。

- 连接器只有设备/应用两页。设备页选择设备后查看归属与能力；系统授权仅能在对应本机完成。应用按搜索、分类、真实图标展示。
- 资源卡用图标和短名称区分类型；动态与资源库分页，图片缓存及阅读文本缓存有上限。人际图谱由记忆文件生成，拖动时更新，不持续运行动画。

## 一体、多端

- 本体：同一套 OpenClaw 加豆豆扩展，支持 Linux、macOS、Windows 部署；一个豆豆只启用一个本体。
- 连接端：Windows、macOS、Android，负责交流、查看内容及授权后的设备执行。暂不做 Linux 连接端和 iOS。
- “创建豆豆”与“连接已有豆豆”是明确模式，不因为安装客户端就启动另一份 Agent。Mac/Windows 可同时作为本体宿主和本机执行端；Android 只连接。
- 迁移本体需要转移同一工作区、配置、凭据与身份，先停止旧本体，再启动新本体；不是两端启动后自动同步。
- 固定上游稳定版本。业务插件、内容约定、主题和客户端单独维护；原生应用的必要修改采用可审查的小补丁。更新走隔离验证与可回滚发布，不直接覆盖在线运行时。

## 一个工作区

```text
workspace/
  SOUL.md                     # 稳定人格与判断原则
  USER.md                     # 用户概况与分类索引
  MEMORY.md                   # 精炼长期记忆，沿用上游维护机制
  DREAMS.md                   # 后台整理报告，产品中隐藏
  memory/
    YYYY-MM-DD.md             # 原生日常记录，保留上游默认路径
    people/<person-id>.md     # 人物字段、关系及事实
    experiences/<domain>.md  # 本人的健康、工作、投资、偏好等
    self/
      reading.md              # 可修订观点的短摘要及原笔记索引
  books/<book-id>/
    source.epub               # 或 PDF 等，有权使用的原文，只读
    text.md                   # 从原文提取，可重建，不是新的权威版本
    notes.md                  # 当前看法、来源定位、修订记录
    shared.md                 # 共同经历引用，不复制用户档案
    reading.md                # 阅读位置、问题与阅读进度
  system/reader-state/<id>.json # 用户的阅读位置与偏好，不是豆豆的进度
  data/
    feed/                     # 动态
    goals/                    # 沿用交办主记录，同时标记用户/自主发起
    journal/                  # 产品日记，书架展示；不复制机器工作日志
    library/                  # 成果与创作
```

旧记忆导入阶段已结束。当前分类文件直接维护事实、时间和必要的不确定性，不再附旧来源文件、脚注或导入进度；旧记忆原文、重复分类归档与对应派生缓存删除，不保留另一套可回填的旧记忆。历史聊天中的导入指令不再执行。

只在有内容时创建分类。人物使用稳定 id 与姓名；性别、年龄、职业等可选且未知留空。其他领域仍按有内容才创建的约定维护。时间、当前状态与必要的旧状态用简短 Markdown 表达。个人事实不由书籍或创作推断生成。

USER.md 与 memory/self/reading.md 是从详细记录提炼的简短摘要/索引，不是独立维护的第二套事实源。修改原记录时一并刷新相关摘要；删除时同步索引并防止自动回填。当前记录优先于旧日志中的过期状态。

个人记忆和书籍检索分语料、标记来源，可以共用搜索基础设施。接入时验证 memory/people/、memory/experiences/ 与 memory/self/ 的深层路径能被实际索引、召回和纠正；必要时显式配置索引路径，不能凭目录名假定生效。书籍原文不进入默认个人记忆语料。

OpenClaw 2026.10.9 的 Dreaming 长期晋升目标是 MEMORY.md；会生成 DREAMS.md、整理状态及可能的日记受管块。它不会任意修订 USER.md 或全部子目录。分类维护与笔记回看属于豆豆业务动作，不能靠移动目录替代。

## 模型与上下文

- 本体从 ZenMux 获取模型目录，连接端按对话、图像、音乐、TTS、视频五类搜索与选择；配置使用部署端 `ZENMUX_BASE_URL` / `ZENMUX_API_KEY` 或私有 `system/zenmux.json`，不开放客户端模型凭据表单。
- 默认对话模型是 `zenmux/deepseek/deepseek-v4.1-flash`。媒体选择按类别做局部更新，不清空其他选择；失败保留最后确认值。
- 当前 ZenMux 已接入对话、图像、TTS、视频协议，音乐没有已接入的 ZenMux 接口契约，显示未接入。目录项可选择不表示已通过推理、额度或生成验证；验证按模型与类别记录。
- 对话的输入上下文/压缩预算目标上限为 272,000 tokens，最大输出目标上限为 128,000 tokens。实际按模型窗口、输出能力和预留输出降低；主会话持续 compact，不自动 reset。未知的上下文、思考档位或媒体参数不在客户端写成已经支持。

## 阅读与主动性

- 默认每日一个空闲阅读窗口，最多十分钟，同时主读一本；定时负责唤醒和预算，不要求读完一本或每次产出笔记。
- 任务主记录保存 next action、等待条件、next wake 和结束条件。reading.md 保存书内位置，不再保存第二份任务生命周期。
- 聊天出现新依据直接修订；每周定向回看变化过或标记待验证的观点。修订当前观点，保留此前判断与变化理由。
- 原文不会训练或永久改变基模参数。持久影响来自少量经过提炼的上下文和相关笔记检索；只有反复检验、影响实际判断的少量摘要才进入 MEMORY.md。
- SOUL.md 提供稳定性格与判断原则，不强迫固定答案；阅读判断可以改变。不把“独立角色”写成拥有已被证明的意识或现实中没有发生的经历。
- 最多三个活跃自主计划，共用交办机制但标记发起者；用户任务优先。模型判断探索内容与分享价值，程序保证调度、预算、去重、免打扰、持久状态与中断恢复。
- 能力申请复用任务等待状态，包含目的、候选服务、权限/费用和替代方案。客户端提供授权、拒绝、稍后；OAuth 在浏览器完成，回调校验并保存凭据，真实探测成功后恢复任务。未支持的服务诚实显示“需要接入”，不能生成装饰性授权按钮。

## 迁移验收

1. 常规部署核对内容、账号和设备资料；用户明确删除的旧记忆和书籍不再另外备份或迁往归档。清理后刷新原生检索索引，验证已删除材料不再被召回。旧节点重新登记能力，未决动作不重放；不保留双内核适配。
2. 同一主会话在多端连续聊天、插话、重连；后台结果不会丢失或误投其他会话。
3. Linux 本体使用远端 Windows 已登录浏览器及明确节点命令；本地桌面截图、点击和输入在真机验证。Android 逐项核验 Phone Use 与 Health Connect。
4. 修订一条个人事实、一次阅读观点后验证检索与客户端均显示新状态；书中虚构故事不会出现在个人档案中。
5. 重启恢复任务，暂停后停止唤醒，设备离线不重复动作；阅读不打断用户消息，后台无实质进展不反复通知。
6. 三平台本体部署与三种连接端分别验收；构建成功不当成安装、实际控制或长期内存稳定的证据。
